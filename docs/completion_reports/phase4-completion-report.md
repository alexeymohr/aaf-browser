## Deviations from the brief

1. **icon.png checked in instead of generated by build.sh.** The brief
   implied a fully automated build chain; in practice generating a
   1024×1024 PNG every build wastes time, and the placeholder design
   only changes when somebody updates `generate_icon.py`. Checked in
   the PNG, kept the regen path documented.
2. **No XML comments in `entitlements.plist`.** Apple's
   AMFIUnserializeXML (used by codesign) rejects them; documented the
   per-key justification in the step-7 commit message instead. Same
   pattern Apple themselves uses for examples.
3. **`prerelease` flag derived in a separate workflow step**, not
   inline in `softprops/action-gh-release@v2`'s `prerelease:` field.
   The inline form would interpolate `github.ref_name` directly into
   shell, which the security hook flagged. Computing the value in
   advance via a separate `id: prerelease` step keeps `secrets` and
   `github.*` references inside `env:` blocks throughout.
4. **Hardened runtime + entitlements applied on Developer-ID builds
   only.** Local ad-hoc builds drop the `--options runtime` flag
   because some macOS versions reject the combo. Local dev iteration
   stays frictionless; CI signed builds get the full runtime
   protection.

## GUI ergonomics — what surfaced in real use

1. **Native file picker via `osascript` is the right call.** No
   PyObjC bloat; the chooser feels native because it *is* native; user
   cancel maps cleanly to a no-op (no nag dialog). The only ergonomic
   miss is the lack of a `.aaf` type filter — the chooser shows all
   files. Adding the filter requires registering a system-wide UTI
   for AAF, which needs Developer ID signing to be persistent. Phase
   5 territory.
2. **Quit link is unobtrusive but findable.** Faded text in the
   topbar, lights up red on hover. Closing the browser tab is the
   actual common action — `beforeunload + sendBeacon` makes that the
   primary teardown path, with the explicit Quit link as a backup
   for users who want to be sure.
3. **Cmd-Q from the Dock works.** The .app bundle gets a Dock icon
   when launched. Cmd-Q sends SIGTERM, which `_app_entry.py` translates
   into `KeyboardInterrupt`, which unwinds to the finally block that
   closes the AAF and shuts the server down. No process leak.
4. **The bundled icon.png placeholder is fine, not great.** "AB"
   letterform on the GUI accent blue. Functional, swap when a real
   logo exists by editing `generate_icon.py` or replacing
   `packaging/macos/icon.png` directly.
5. **`.aaf` open-with from Finder works on cold start only**, as
   documented in the README. In v1, double-clicking another .aaf
   while the app is already running is a no-op. Implementing
   in-process open-with would require an AppKit event loop —
   defer to Phase 5 if it becomes annoying.

## Risks that didn't materialize

The brief flagged several risks; here's how they actually played out:

- **pyaaf2 dynamic class registration** — `collect_submodules('aaf2')`
  was sufficient. The bundled app loads 4,648 Mobs from the 2.3 GB
  session and walks chains correctly. No additional `hiddenimports`
  needed.
- **Port 5173 collision** — irrelevant; `_app_entry.py` uses
  ephemeral-port assignment via `socket.bind(('127.0.0.1', 0))`.
- **wsgiref blocking on long find walks** — same risk as Phase 2. No
  worse in the bundle; documented as a v1 limitation in the README.
- **Cmd-Q SIGKILL** — the SIGTERM handler converts to KeyboardInterrupt
  before SIGKILL fires, so cleanup runs. pyaaf2 is read-only so a
  rogue SIGKILL wouldn't have hurt anyway.
- **CI cert leakage** — workflow imports the cert into a temp keychain
  and deletes it in the cleanup step (always-runs). Standard pattern.

## Recommendations for a possible Phase 5

No commitment, but the following came up while building:

1. **Replace wsgiref with a threaded WSGI server** so a slow
   `/api/find` doesn't block `/api/quit` or other reads. Options:
   gevent's WSGIServer (single-thread, non-blocking) or
   `werkzeug.serving.run_simple(threaded=True)` (Werkzeug works fine
   under PyInstaller; the 35 s lag we saw earlier was a teardown
   issue, not a runtime issue). Same pyaaf2 lock semantics either way.
2. **Auto-update via Sparkle.** Requires Apple Developer ID (which
   we'll have), an `appcast.xml` hosted somewhere, and the
   sparkle-project.org framework bundled. Mid-effort but high user
   value once there are >5 users.
3. **In-process `NSApplicationOpenFile` handling** so double-clicking
   an .aaf while the app is running preloads it. Requires PyObjC and
   an AppKit event loop running alongside the wsgiref server — not
   trivial. Probably worth it once enough users hit the cold-start-
   only limit.
4. **A real logo**, properly designed, with full `.iconset` artwork
   tuned for each size band (the algorithmic shrink we do today
   produces an OK 256×256 but a slightly muddy 32×32).
5. **Universal2 builds** if any user with an Intel Mac surfaces a
   need. The CI workflow currently targets `macos-latest` (arm64);
   adding a parallel intel job would double the .dmg matrix.
6. **Code signing on local builds.** Right now the local build script
   needs `CODESIGN_IDENTITY` to be set in the env or it falls back to
   ad-hoc. Adding a one-time `local.env` (gitignored) that exports
   the env var would simplify dev iteration on signed bundles.
